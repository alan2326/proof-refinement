## Mathematical insight (required, ≤ 5 sentences)

The existing `F_inv_*_deriv_bound_core` lemmas in `Lemma54_Paper_Cauchy.lean:32,52,66,85,124` use a recentered Cauchy contour of radius `(1-r)/2`, which gives `‖h_z‖ ≤ R/((1-r)/2) = 2R/(1-r)` and `‖u_zz‖ ≤ 2R/((1-r)/2)² = 8R/(1-r)²`; the factor `/2` was a conservative-by-default choice in the original proof, not a mathematical necessity. The actual constraint `add_mem_disk_r1` (line 36) is `‖z₀+w‖ ≤ ‖z₀‖ + ‖w‖ < r + ρ` and `r + ρ < 1` requires only `ρ < 1-r`, so any `ρ = (1-r)·k` with `k < 1` works; the recentered ball still lies inside `disk r₁ = ball 0 1`. Picking `k = 9/10` gives `‖h_z‖ ≤ R/((1-r)·9/10) = (10R)/(9·(1-r))`, an `1.111·R/(1-r)` upper bound vs the current `2R/(1-r)` — a `1.111/2 = 0.556×` reduction in `invFp` (i.e., `invFp²` drops by `(0.556)² ≈ 0.309` factor), while `‖u_zz‖` drops to `2R/((1-r)·9/10)² = (200R/81)/(1-r)² ≈ 2.469·R/(1-r)²`, a `0.309×` reduction from the current `8R/(1-r)²`. Both reductions feed multiplicatively into the Cr_phi formula `M_phi·M_phi_prime·invFp² + (R/((1-r)·k)²)·M_phi²`, so the total `Cr_phi2 ≈ 0.66 + 0.51 = 1.17` vs V9's `Cr_phi ≈ 3.79` — a 3.24× reduction in `Cr_phi`, allowing `Cr_val` to drop from `5` to `2` (or `1` with deeper `k → 1` and a tighter monotonicity proof — the contract chooses `2` for safe margin). The mathematical lever is identical to the standard Cauchy-on-disk technique that's already in production; we are simply *parameterizing* the contour ratio that was implicitly fixed at `1/2` in the original proof, an internal slackness that has no analytic content.

## Why (≤ 3 sentences, must include numerical evidence)

`Scratch/sprint_013_planner_cauchy_radius.py` (output below) computes the exact `Cr_phi2` value at V9 parameters using `M_phi_val = 239/5000`, `M_phi_prime_val = 543/10000`, `R_max = 23/20`, `1-r = 2/25`, `k = 9/10`: `invFp = R/((1-r)·k) = (23/20)/(2/25·9/10) = 575/36 ≈ 15.972`, `invFp² = 330625/1296 ≈ 255.11`, `term1 = M_phi · M_phi_prime · invFp² = 239/5000 · 543/10000 · 330625/1296 ≈ 0.6622`, `term2 = (R/((1-r)·k)²) · M_phi² = (23/20) · (50/9)² · (239/5000)² ≈ 0.5069`, total `Cr_phi2 = 121203353/103680000 ≈ 1.1690`. Setting `Cr_val := 2` leaves margin `2 - 1.169 = 0.831`, comfortable for `nlinarith` on the closed-form polynomial in `R`. For comparison, the script also evaluated `k = 99/100` (`Cr_phi2 ≈ 0.9661`, would allow `Cr_val = 1` with margin `0.034` — too tight for safe `nlinarith`) and `k = 1/2` (recovers V9's `Cr_phi = 3.79` exactly, confirming the formula is consistent with the existing one). The sprint targets `k = 9/10` and `Cr_val = 2` as the right tradeoff between numerical aggressiveness and `nlinarith` robustness.
