## Mathematical insight (required, ≤ 5 sentences)

The auxiliary z-identity `DD · h_z² + D · u_zz = 0` (`F_inv_aux_z_identity` in `Lemma54_Paper_Pderiv_Single.lean:87`) gives `‖u_zz‖ = ‖DD‖ · ‖h_z‖² / ‖D‖`, and combined with `‖h_z‖ = 1/‖D‖` (the first-deriv identity) this becomes `‖u_zz‖ = ‖DD‖ / ‖D‖³ = ‖DD/D³‖` — a single analytic function on the rectangle, NOT a product of two independent sup-bounds. V11 bounded this by `(sup ‖DD‖) · (sup 1/‖D‖)³ = M_pp · inv_F_p_z³ ≈ 56.08 · 8 = 448.6`, but the actual `sup_w ‖DD/D³‖` is much smaller — at p=0 the closed-form arcsin derivatives give the remarkable identity `H_0''(w) / H_0'(w)³ = w` exactly (since `H_0'(w)³ = (1-w²)^{-3/2}` and `H_0''(w) = w·(1-w²)^{-3/2}` cancel cleanly), so `g(0, w) = |w| ≤ √((1-δ)² + B²) ≈ 1.394` over the rectangle Ω(1635/10000, 1115/1000), and at η=1/100 the worst-case η-correction adds at most ~10% (yielding ≤ 1.55), so `u_zz_bound_val := 2` is a comfortable rational ceiling. The analytic-function-quotient `g(p, w) := ‖((1-p)H_0''+p·H_eta'') / ((1-p)H_0'+p·H_eta')³‖` is bounded uniformly in `p ∈ [0, 1]` by Cauchy-on-enlarged-rectangle (the same machinery `Numerical_Library/m_pp.py` already uses for `H_eta''`, applied to the quotient), making a direct arb-certified `compute_u_zz_bound` straightforward to mint inline. This is a *structural* improvement: replacing a triangle-decomposed sup-product (`sup A · sup B`) with a sup of the actual product (`sup AB`) — fundamentally tighter for any analytic function family that doesn't simultaneously attain both factor-sups at the same point.

## Why (≤ 3 sentences, must include numerical evidence)

`Scratch/sprint_016_planner_uzz_direct.py` confirms via direct mpf computation: at V11's rectangle (δ=1635/10000, B=1115/1000), the closed-form identity `H_0''(w)/H_0'(w)³ = w` makes `sup_w ‖DD/D³‖ at p=0 = sup_w |w| = √((1-δ)² + B²) ≈ 1.3939` — a 321.86× factor smaller than V11's `M_pp · inv_F_p_z³ = 448.64`. Setting `u_zz_bound_val := 2` (rational, plenty of margin for the η=1/100 correction at p > 0) gives `term2 = (1/2) · 2 · M_phi² = (239/5000)² = 57121/25000000 ≈ 0.002285`, and `Cr_phi_uzz_direct = term1 + term2 = 519108/50000000 + 114242/50000000 = 633350/50000000 ≈ 0.01267`, leaving margin `1/32 - Cr_phi_uzz_direct = 1562500/50000000 - 633350/50000000 = 929150/50000000 ≈ 0.01858` against `Cr_val := 1/32 = 0.03125` — a 32× reduction over V11's `Cr_val = 1` and ~2.6·10¹⁶× cumulative reduction from V0's ~8.2·10¹⁴. The new oracle is *exactly* oracle-shaped (`∀ p ∈ Ioo 0 pr, ∀ w ∈ oracle_domain, ‖<analytic expression>‖ ≤ <bound>_val`) so it qualifies for the Generator's "Inline oracle creation" recipe — no proposal needed; the runtime arb pipeline re-verifies it every audit.
