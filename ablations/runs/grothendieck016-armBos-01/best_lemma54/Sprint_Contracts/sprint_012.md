## Goal (one sentence)

Define a new theorem `F_inv_p_second_deriv_bound_phi` in `Proof/Lib/Lemma54_Paper_Pderiv_Single.lean` that bounds `‖∂²_p F_inv‖ ≤ 2 · Cr_phi r M_phi M_phi_prime R` where `Cr_phi := M_phi · M_phi_prime · invFp² + (4R/(1-r)²) · M_phi²` (with `invFp := 2R/(1-r)`); plumb it through to a new wrapper `lemma_5_4_paper_on_domain_phi` in `Lemma54_Paper_Main.lean`; and create `Candidates/V9.lean` consuming `h_M_phi_oracle` and `h_M_phi_prime_oracle` (already registered in `lemma.toml`) to set `Cr_val := 5` (a small integer dominating the literal rational `Cr_phi r_val M_phi_val M_phi_prime_val (R_val_paper r_val) ≈ 3.79`), driving `Cr_val` from V8's `1132310000` to `5` — a `2.26·10⁸×` reduction.

## Mathematical insight (required, ≤ 5 sentences)

The existing proof of `F_inv_p_second_deriv_bound_paper` (and `_tight`) at `Lemma54_Paper_Pderiv_Single.lean:207-730` produces the intermediate inequality `‖u''‖ ≤ 2 · ‖Φ'‖ · ‖Φ‖ · invFp² + ‖u_zz‖ · ‖Φ‖²` (lines 654-663) where `Φ = H_η - H_0` is the deformation difference and `‖u_zz‖ ≤ 8R/(1-r)²` is the existing Cauchy-on-disk-r₁ bound (line 665), then weakens `‖Φ‖, ‖Φ'‖ ≤ 2M` via the trivial triangle inequality on the four sup bounds in `h_M_oracle` — this triangle step is *the* loose link at small η. At `η = 1/100` the deformation `Φ = H_η - H_0` is `O(η)` (since `H_η` interpolates linearly to `H_0` as η → 0), so the certified-arb oracle `compute_M_phi_bound` produces `M_phi ≈ 0.048` (vs the triangle's `2M = 856`) and `compute_M_phi_prime_bound` produces `M_phi_prime ≈ 0.054` — both already certified at production-grade `(n_per_edge=512, prec=200, K_max=80)` on the V8 oracle rectangle `Ω(1635/10000, 1115/1000)`, per `Scratch/sprint_proposal_001_smoke.py`. Replacing the two triangle steps `‖Φ‖ ≤ 2M` and `‖Φ'‖ ≤ 2M` with the η-aware oracle bounds gives `‖u''‖ ≤ 2 · M_phi_prime · M_phi · invFp² + (8R/(1-r)²) · M_phi²`, defining `Cr_phi := M_phi · M_phi_prime · invFp² + (4R/(1-r)²) · M_phi²` so that `‖u''‖ ≤ 2 · Cr_phi`. Crucially, the `M_pp` oracle from proposal_001 is NOT used — at V8 parameters `invFp³ ≈ 23764`, so the implicit-function chain `‖u_zz‖ ≤ M_pp · invFp³` would give a worse bound than the existing direct Cauchy `‖u_zz‖ ≤ 8R/(1-r)² ≈ 1437.5` even at the cleanest M_pp ≈ 56.31; the proposal_001 status log confirmed this and recommends keeping the Cauchy step (this sprint follows that recommendation exactly).

## Why (≤ 3 sentences, must include numerical evidence)

`Scratch/sprint_012_planner_cr_refined.py` (output below) computes the *exact* `Cr_phi` value at V8 parameters using rational upper bounds on the smoke values (`M_phi_val = 239/5000 ≥ 0.0476`, `M_phi_prime_val = 543/10000 ≥ 0.0541`): term1 = `M_phi_prime · M_phi · invFp² = 543/10000 · 239/5000 · 13225/16 ≈ 2.1454`, term2 = `(4R/(1-r)²) · M_phi² = (4·23/20)/(2/25)² · (239/5000)² ≈ 1.6422`, total `Cr_phi = 121203353/32000000 ≈ 3.7876`; rounding up to the next integer with safety margin yields `Cr_val = 5` (a `2.26·10⁸×` reduction from V8's `1132310000`). For comparison, the script also computed the *full* `Cr_refined` (consuming all three proposal_001 oracles, including M_pp) at `Cr_refined ≈ 1549.59` — *409× WORSE* than `Cr_phi` because `M_pp · invFp³ ≈ 56·23764` dominates term2. The hybrid (M_phi + M_phi_prime + retained Cauchy on `‖u_zz‖`) is therefore decisively the right move; the M_pp oracle remains in `lemma.toml` for a future regime where the rectangle shrinks enough to make `invFp` small.
